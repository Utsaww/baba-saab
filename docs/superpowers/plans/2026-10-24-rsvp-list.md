# RSVP List Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Save every live RSVP, give staff an RSVP page (totals, per-event headcounts, table, CSV, add/edit/remove, family link, "new" badges) and give families a private read-only page — while the guest still gets WhatsApp opened.

**Architecture:** New `Rsvp` model keyed by `invitationId` + `rsvpKey` (`<phoneKey>#<nameKey>`, or `staff#<uuid>`), and an `RsvpLimit` model with DynamoDB TTL for rate limits. A new guest-callable Lambda `rsvp-guest` serves `submitRsvp` (called by the Next route `POST /api/rsvp`, which adds a salted IP hash) and `familyRsvps` (token-checked read). Staff use Amplify model operations on `Rsvp` plus two new mutations on the existing `invitation-publish` Lambda (`regenerateFamilyToken`, `markRsvpsSeen`). Pure helpers in `src/InvitationModule/lib/rsvpList.js` compute keys, totals, the "same family" marker, filters and CSV for both pages. The Phase 5 erase also deletes an invitation's RSVPs.

**Tech Stack:** Next.js 14.2 (JS, `@/*`), Tailwind, Vitest 2 + Testing Library; Amplify Gen 2 (`amplify/`, TS), `@aws-sdk/lib-dynamodb`, node `crypto`.

**Spec:** `docs/superpowers/specs/2026-10-24-rsvp-list-design.md` (binding).

## Global Constraints

- Branch `feature/rsvp-list`; never commit to `main`; never stage `amplify_outputs.json`; owner may have a dev server on :3000 — don't kill processes you didn't start; build from a scratch copy if `.next` is in use.
- Duplicate rule (D6): same phone **and** same name (case-insensitive, spaces collapsed) → overwrite; same phone + different name → new row. "Same family" marker text: `Same family as <names> — replied from the same phone number` (names joined with ", ").
- Phone key = `whatsappDigits(phone)` from `src/InvitationModule/lib/rsvp.js` (the Lambda mirrors it, with identical tests).
- Rate limits: 5/hour per phoneKey; 60/hour per IP hash. IP hash = `sha256(ip + (process.env.RSVP_IP_SALT ?? "baba-saab-rsvp"))` computed in the Next route.
- Guest function enforcement reads the **published** copy: `status === "published"`, `whatsappRsvpOn(publishedContent.rsvp)`, valid family number, `!isRsvpClosed(publishedContent.rsvp)`, honeypot empty, `validateRsvpInput` passes.
- Guest copy (exact): saved → `Your reply is saved. Send it on WhatsApp to let the family know personally.`; save failed / rate-limited → `We couldn't save your reply — your WhatsApp message still reaches the family.`; closed → existing closed notice, no WhatsApp.
- Family page: `noindex`, `Referrer-Policy: no-referrer`, `Cache-Control: no-store`, read-only, shows phone numbers; not available text `This link is no longer available` (404). Works for draft/published/offline, never deleted.
- New family link confirm: `The old family link will stop working.`
- Totals: people = sum of `guestCount ?? 1` over `attending === "yes"`; per-event people likewise, where a reply with empty `eventIds` counts for every event; maybe/no never counted as people.
- CSV: UTF-8 with BOM (`﻿`), CRLF lines, RFC 4180 quoting; columns `Name, Phone, Attending, People, Events, Meal, Message, Replied, Source`.
- Tokens: `randomBytes(16).toString("base64url")`.
- After any dependency change: `npm install --package-lock-only` + clean-copy `npm ci`.
